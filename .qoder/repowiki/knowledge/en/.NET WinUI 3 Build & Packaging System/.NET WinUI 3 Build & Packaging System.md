This project uses the modern .NET SDK-style build system for a WinUI 3 desktop application targeting Windows 10+. The build is driven by MSBuild through `.csproj` files with centralized global properties and per-platform publish profiles.

**Core build tooling:**
- **.NET 10 SDK** pinned via `global.json` (version `10.0.100`, rollForward to latest feature, prereleases allowed)
- **SDK-style `.csproj`** (`Agentic.Desktop/Agentic.Desktop.csproj`) using `Microsoft.NET.Sdk` with `<OutputType>WinExe</OutputType>` and target framework `net10.0-windows10.0.26100.0`
- **Solution file** uses the new `.slnx` format (`Agentic.Desktop.slnx`) referencing both the WinUI app and the shared `Agentic.ACPLibrary` project
- **Global props** in `Directory.Build.props` enforce cross-project conventions: nullable references enabled, implicit usings enabled, C# latest language version

**Multi-targeting & platforms:**
- Three CPU architectures supported: `x86`, `x64`, `ARM64` declared via `<Platforms>`
- Runtime identifier auto-detected from host architecture when not explicitly set
- Per-architecture publish profiles under `Properties/PublishProfiles/` (e.g., `win-x64.pubxml`) configure self-contained single-file or framework-dependent publishing to `bin\$(Configuration)\$(TargetFramework)\$(RuntimeIdentifier)\publish\`

**Packaging & distribution:**
- **MSIX packaging** enabled via `<EnableMsixTooling>true</EnableMsixTooling>` and the `Microsoft.WindowsAppSDK` NuGet package, allowing Visual Studio "Package and Publish" context menu
- **WinApp SDK integration** through `Microsoft.Windows.SDK.BuildTools.WinApp` which enables `dotnet run` on packaged apps by registering debug identities
- Application manifest defined in `app.manifest`; resources declared as `<Content>` items including splash screen, logos, and icons

**Publishing behavior:**
- Debug builds: no ReadyToRun, no trimming
- Release builds: ReadyToRun compilation enabled, assembly trimming enabled for smaller binaries
- Self-contained deployment configured in publish profiles

**Localization build:**
- Resources stored as `.resw` files under `Strings/{locale}/Resources.resw` (en, ja, zh-CN, zh-TW)
- A PowerShell helper `validate_resw.ps1` validates resource XML structure

**Dependencies managed via NuGet packages** referenced directly in the `.csproj`: Markdig, CommunityToolkit.Mvvm, Microsoft.Extensions.Logging.Debug, ShihaoShen.Agentic.ACPLibrary, and Windows App SDK components.
