This repository uses the standard .NET dependency management approach based on NuGet packages and SDK-style project files. Dependencies are declared directly in the `.csproj` file using `<PackageReference>` elements, and there is no separate `packages.config` or explicit lockfile committed to version control.

**System and tools used:**
- **NuGet** as the package manager for third-party libraries
- **.NET SDK 10.0.100** pinned via `global.json` with `rollForward: latestFeature` and pre-release packages allowed
- **SDK-style projects** (`Microsoft.NET.Sdk`) that automatically handle package restoration
- **Directory.Build.props** at the solution root to enforce common C# language settings (Nullable, ImplicitUsings, LangVersion)
- **MSIX packaging** enabled via `EnableMsixTooling` and `Microsoft.Windows.SDK.BuildTools`

**Key files:**
- `Agentic.Desktop/Agentic.Desktop.csproj` — declares all NuGet package references including Markdig, Microsoft.WindowsAppSDK, CommunityToolkit.Mvvm, Microsoft.Extensions.Logging.Debug, Microsoft.Windows.SDK.BuildTools.WinApp, and the internal `ShihaoShen.Agentic.ACPLibrary` package
- `global.json` — pins the .NET SDK version and allows pre-release roll-forward
- `Directory.Build.props` — centralizes build properties applied to all projects in the directory tree
- `Agentic.Desktop.slnx` — solution file referencing both the desktop app and the shared ACPLibrary project

**Architecture and conventions:**
- All dependencies are declared inline in the project file rather than through a separate manifest
- The shared library `ShihaoShen.Agentic.ACPLibrary` is consumed as a NuGet package (version `0.1.0-beta.3`) even though it appears to be part of the same solution, suggesting a private NuGet feed or local package source configuration
- No `nuget.config` file is present at the repository root, so package sources rely on default NuGet.org and possibly global machine-level configuration
- Package versions are explicitly pinned (no floating versions), ensuring reproducible builds
- Build-time tooling like `Microsoft.Windows.SDK.BuildTools.WinApp` is included as a development dependency

**Rules developers should follow:**
- Add new dependencies by editing the `<ItemGroup>` with `<PackageReference>` entries in `Agentic.Desktop/Agentic.Desktop.csproj`
- Always specify an explicit version number for packages to ensure deterministic builds
- Do not commit generated files like `*.nuget.props` or `*.nuget.targets` (already excluded in `.gitignore`)
- Use the pinned .NET SDK from `global.json` when building to maintain consistency across environments
