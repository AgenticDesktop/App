本仓库未采用传统意义上的配置文件（如 appsettings.json、.env、.yaml 等）来管理应用配置。配置系统非常轻量，主要通过以下机制实现：

1. **启动配置**：`Properties/launchSettings.json` 仅定义 MSIX Package 和 Unpackaged 两种调试运行 profile，不包含应用级配置项。
2. **运行时参数**：应用的核心配置（Agent 路径、参数、工作目录）由用户在 SettingsPage 中通过 UI 输入，保存在 `SettingsViewModel` 的 `[ObservableProperty]` 字段中（`_agentPath`、`_agentArguments`、`_workingDirectory`），以内存单例形式跨页面共享（`SettingsViewModel.Shared`）。
3. **全局状态**：连接后的 `IAcpClient` 实例通过 `App.CurrentAcpClient` 静态属性在应用生命周期内共享，并通过 `App.SetAcpClient()` 和 `AcpClientChanged` 事件通知订阅者。
4. **日志配置**：在 `App.OnLaunched` 中使用 `Microsoft.Extensions.Logging.LoggerFactory.Create` 配置 Debug 输出，最小级别为 Debug。
5. **本地化资源**：多语言字符串通过 `Strings/*/Resources.resw` 文件管理，由 `LocalizationService` 提供访问。

设计决策：
- 没有持久化存储用户设置（重启后不保留 Agent 路径等配置）
- 使用 MockAgentTransport 支持无 Agent 的模拟模式（当 AgentPath 为空时）
- 配置与业务逻辑耦合在 ViewModel 中，未抽象出独立的 Configuration 服务

开发者应遵循的规则：
- 新增配置项应在 SettingsViewModel 中添加对应的 `[ObservableProperty]` 并在 SettingsPage 中暴露 UI
- 需要跨页面共享的状态通过 App 静态属性或 SettingsViewModel.Shared 访问
- 避免引入外部配置文件依赖，保持 WinUI 桌面应用的简洁性
