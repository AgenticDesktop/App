## 1. 系统/方法概述
该 WinUI 3 桌面客户端采用 .NET 标准异常模型进行错误处理，没有自定义错误类型或统一错误码体系。错误主要通过抛出标准 .NET 异常（如 UnauthorizedAccessException、OperationCanceledException）向上层传播，在 UI 层通过 try/catch 捕获并转换为本地化消息展示给用户。

## 2. 关键文件与位置
- **App.xaml.cs**：应用级日志配置（Microsoft.Extensions.Logging），最低级别设为 Debug，输出到调试器
- **Services/FileSystemHandler.cs**：路径验证失败时抛出 UnauthorizedAccessException
- **Services/TerminalManager.cs**：终端进程管理，大量使用空 catch 块吞掉异常
- **ViewModels/ChatViewModel.cs**：核心业务异常处理，将异常消息格式化后追加到聊天消息中
- **Mocks/MockAgentTransport.cs**：Mock 传输层通过 TransportFaulted 事件上报异常

## 3. 架构与约定
- **无全局异常处理器**：未注册 Application.DispatcherUnhandledException 或 AppDomain.CurrentDomain.UnhandledException 处理器
- **分层异常处理**：Service 层抛出具体异常，ViewModel 层捕获并转换为 UI 友好的消息
- **取消操作特殊处理**：OperationCanceledException 被单独捕获并忽略，表示用户主动取消
- **日志记录**：仅通过 Microsoft.Extensions.Logging 输出到调试器，无持久化日志
- **错误信息本地化**：使用 LocalizationService.Format() 包装错误消息，支持多语言

## 4. 开发者应遵循的规则
- **不要吞掉所有异常**：TerminalManager.cs 中存在多处 `catch { }` 空捕获，应避免静默失败
- **区分可取消异常**：OperationCanceledException 应单独处理，不应作为普通错误展示
- **使用具体异常类型**：如 FileSystemHandler 中的 UnauthorizedAccessException，便于上层识别和处理
- **避免在 finally 中抛出异常**：确保清理逻辑不会掩盖原始异常
- **异步操作需正确处理取消令牌**：所有 async 方法应支持 CancellationToken
- **UI 层不直接处理底层异常**：应在 Service 层抛出有意义的异常，由 ViewModel 统一转换
